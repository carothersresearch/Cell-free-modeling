# Predictive analysis of lysate-based cell-free metabolism enabled by automated construction of mechanistic kinetic models

Code to reproduce the figures in the manuscript, plus two supporting pieces of work: a parameter-set filtering pipeline that produces the kinetic parameter ensemble used throughout the figures, and a synthetic-data experiment used to validate the fitting/inference approach.

All notebooks in this folder are self-contained.

## `filtering_parameter_sets/`

`filter.ipynb` runs a series of consistency checks ("dummy tests") against sampled kinetic parameter sets — e.g. HCT increasing citrate, NADH consumption, glycine production from serine, NADH regeneration, and overall pathway efficacy — and filters down to the parameter sets that pass. Outputs:

- `all_labels_parameters_error.dat` / `top3_labels_parameters_error.dat` — per-parameter-set error/labels from the filtering runs.
- `final_params.pkl` — the filtered parameter set ensemble consumed by Figures 4–6. This file is too large to upload directly, so instead you'll have to extract it from:
- `final_params.tar` / `final_params.7z` — compressed archives of the same parameter set (for storage/transfer).

## `synthetic_data_experiment/`

A validation experiment, separate from the main figures, that generates synthetic datasets from the kinetic model:

- **make_perfect_dataset.ipynb** — simulates the base model (`iMC057.txt`) from a grid of starting conditions, including specific enzyme knockout/overexpression variants (e.g. `200X_mdh_neg`, `200X_pyc`), to produce noiseless ("perfect") ground-truth datasets.
- **make_diff_datasets.ipynb** — perturbs kinetic parameters/enzyme/metabolite priors and regenerates an Antimony model from those priors, then simulates high/medium/low-quantity experiment sets with high/medium/low observation noise added, to test how dataset size and quality affect downstream fitting.
- `perfect_datasets.zip` / `synthetic_datasets.zip` — generated output datasets from the two notebooks above.

## `LLM_analyses/`

Analyses performed by Claude Code (Claude Sonnet 4.6) using iMC057 as a simulation environment, relevant to Figures 6 and 7. Claude Code was given `model/iMC057.txt` and `Claude.md`, wrote the scripts in `scripts/` itself, and ran all simulations through them. `Claude.md` is the project instructions file: it describes the lysate system, the malate/rTCA pathway and base-case recipe, the tunable variables and their bounds, and how to load and parameterize the model. Run scripts from inside `LLM_analyses/`, and first extract `final_params.pkl` (see `filtering_parameter_sets/`) to `LLM_analyses/parameters/final_params.pkl`.

- `Claude.md` — instructions/context file provided to Claude Code (also records conventions and corrections learned during the analyses).
- `model/iMC057.txt` — base kinetic model, identical to the one at the repository root.
- `model/pathways/` — 30 Antimony models, each the base model with one heterologous pathway spliced in, named `<Substrate>_<n>_<Product>.txt` (10 starting substrates × 3 pathways each).

**Shared simulation code**

- `sim2.py` — simulation harness: loads iMC057 with the representative parameter set (index 60), applies dilution, enzyme expression, and metabolite additions, and tracks cumulative malate produced via rTCA (R25) vs. TCA (R20).
- `loader.py` — loads Antimony models with antimony + libRoadRunner directly (equivalent to `te.loada`).
- `species_param_map.json` — species → parameter/reference-constant mapping parsed from iMC057, used to set target concentrations.
- `jitter_lib.py`, `campaign_jitter_lib.py` — Monte Carlo kinetic-parameter jitter engines (N=30 log-normal draws around index 60). `campaign_jitter_lib.py` is used for Figure 6; `jitter_lib.py` is an earlier version of the root-level `figure_ensembles.py`.
- `paper_style.py` — shared palette, fonts, and panel-label helpers for the publication figures.

**Malate/rTCA design campaign (Figure 6)**

- `campaign.py` — 100-design exploration campaign spanning dilution, heterologous enzyme expression, native-enzyme knockdowns, and metabolite supplementation.
- `analyze_designs.py` — random forest feature importance, clustering, and correlation analysis of the campaign designs (6A).
- `factorial_analysis.py` — full 2⁴ factorial decomposition of the best design (dilution, citrate synthase knockdown, fumarase knockdown, serine loading) into single-lever contributions and synergy (6B).
- `citrate_synthase_synergy_analysis.py` — citrate synthase flux and knockdown effect across dilution factors, plus acetyl-CoA time courses (6C–F).
- `run_jitter_fig6a.py`, `run_jitter_fig6b.py`, `run_jitter_fig6cdef.py` — parameter-jitter uncertainty for each Figure 6 panel.
- `fig_malate_campaign.py` — assembles Figure 6; `fig_panel_d_standalone.py` exports panel D on its own.

**Heterologous pathway diversification (Figure 7)**

- `pathway_designs.py` — the 30 pathway designs: enzymes, substrate and dose, cofactor additions, and module classification.
- `ec_map.py`, `kegg_species_map.py` — enzyme name → EC number and KEGG compound → model species mappings.
- `frenda_kinetics.py` — parses FRENDA output (BRENDA-measured or CatPred-predicted kcat/Km, eQuilibrator Keq) into per-EC kinetics, including documented manual overrides for ECs FRENDA could not resolve correctly.
- `pathway_generator.py` — writes `model/pathways/*.txt` by splicing each design into iMC057 as modular rate-law reactions.
- `run_pathway_sims.py`, `compile_results_table.py` — simulate all 30 pathways (D=10, 4 h) and compile the results table (Figure 7).
- `analyze_pathway_space.py`, `module_dilution_analysis.py` — what distinguishes high- from low-performing designs, and why native modules respond differently to dilution.
- `optimize_pathways.py`, `titer_range_study.py` — 7×7 grid of dilution factor (D=10–400) × substrate loading (1–100 mM) per pathway, used to find each pathway's optimum and achievable titer range (Figure 8).
- `plot_pathway_map.py`, `plot_titer_ranges.py`, `plot_optimization_results.py`, `plot_timecourses.py` — substrate→product map, titer-range dumbbell plot, optimization improvement, and time courses.

`generate_supplement.py` builds the supplementary-methods document summarizing both analyses.
